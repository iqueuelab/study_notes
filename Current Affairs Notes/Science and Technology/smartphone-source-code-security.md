# Smartphone security standards and source-code access

## January 2026: report and official clarification
- The daily source reports possible smartphone-security requirements under the **Indian Telecom Security Assurance Requirements (ITSAR)**: source-code vulnerability analysis in Indian labs, restrictions on background access to camera/microphone/location, **12-month logs**, malware scanning and prior information about major updates. These are **reported discussion points**, not demonstrated enacted obligations.
- **11 January 2026 MeitY clarification:** the Ministry **refuted the report that government was proposing to force smartphone manufacturers to share source code**, describing routine stakeholder consultations and an open approach to industry concerns. Do not turn the newspaper headline into a settled mandate. [Official clarification](https://www.pib.gov.in/PressReleasePage.aspx?PRID=2213520&lang=1&reg=1).
## Technical and governance significance
- **Source code** is human-readable programming instructions; access can expose implementation choices and intellectual property. Review can help detect vulnerabilities/backdoors, but security depends on audit quality, confidentiality, secure access and remediation. Encryption algorithms, secret cryptographic keys and source code are distinct.
- Phones store payment credentials, personal communications and identity data: compromised software can cause fraud, identity theft and privacy loss. Secure defaults, permission control, authenticated updates and vulnerability response support protection.
- Assess proposed logging/auditing against data minimisation, proportionality, access controls, cost and prompt patch delivery. Continuous scanning has performance/battery trade-offs; testing requirements must not delay urgent security fixes. The source's sweeping claim of no precedent anywhere is unverified.
- **Sanchar Saathi:** the earlier mandatory pre-installation direction was withdrawn in December 2025; voluntary app availability continued, as already covered in its separate topic. This controversy does not itself establish a source-code disclosure obligation.
